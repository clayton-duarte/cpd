## Lessons made reproducible

1. Put common method in one copyable package; keep repo facts/config/decisions
   separate. Do not make a new agent remember a conversation, CPD service,
   absolute tool path or provider-specific UI.
2. Define iteration/run/day/reset precisely. Use intent-only run descriptors and
   atomic GitHub run markers to enforce lower caps across fresh sessions; a
   handoff's copied totals are not a ledger.
3. Prove through real callers/guards. #1137 needed actual hub teardown evidence;
   accepting work in a permissive fake alone was insufficient.
4. Keep minimal runnable fixtures and commands in durable issues/commits, not
   only ephemeral workspaces. State source-confirmed versus runtime evidence.
5. Update CI state when it finishes. CI found a second stale token fixture;
   correction belongs on the same PR, and unexpected broader failures need a
   same-environment base comparison before attributing them to a fix.
6. Preserve researched contradictions and explicit decisions. #1145's shared-
   token compatibility question is labelled for the User, not silently resolved.
7. Account allowance is independent of issue/PR caps. Record dated readings and
   uncertainty; useful work and review capacity determine throughput.
8. No next run is started by this distillation. A new agent reads the kit,
   project profile/config and canonical handoff, rechecks GitHub, and resumes
   only a User-started run with the same descriptor.
