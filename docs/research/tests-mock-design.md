# tests-mock design: how the whole suite reaches the rule (Job `design`, attempt `design-a1`)

Static design. Nothing run but two throwaway scratch crates (built in `/tmp`, removed) to check Cargo's `CARGO_BIN_EXE` rules. Findings files are `T-<name>` = `docs/research/tests-mock-<name>.md`. **verified** = read in the source or run here; **unverified** = inferred.
Rule: tests test only our code; tmux, pi, gh, curl, ssh, the network and real waiting are mocked; git is mocked except a few adapter contract tests; no leak, flake, sleep or orphan.
Scope (audit totals, `rg -c '#\[(test|tokio::test)'`): Rust 3,295 = units 1,342 (T-units:3) + engine 191 + store 110 (T-engine:7) + session 167 (T-session:60) + tooling 201 (T-tooling:17) + tui 365 (149 T-tui-a:19-33 + 216 T-tui-b:46) + flow 508 (321 T-flow-a:30 + 187 T-flow-b:6) + pr 411 (217 T-pr-a:23 + 194 T-pr-b); TypeScript about 963 (T-pi: 511 + 452, approximate, unverified against `node --test`). The Gate runs 3,237 Rust tests (`.config/nextest.toml:67`, comment).

## 1. The fake tmux

**Why a binary on PATH, and no product change.** The adapter is a concrete struct that runs `tmux -u -L <socket> -f /dev/null <args>` from `PATH` (`core/src/host/tmux.rs:501-516`, `PROGRAM` `:51`) with `TMUX_TMPDIR` set by the harness (`:518-531`); `Tmux::with_program` (`:483`) already redirects it. `TestEnv::command` builds `PATH = env.bin() ++ inherited` (T-pi §2.3, `cli/tests/common/mod.rs:854-856`), so a `tmux` in `env.bin()` wins for `cpd`, for the scripts the tests run, and for the engine. A trait seam in `Tmux` would not reach the built `cpd`, which is a separate process (the same reason for git, §3).

**Where it lives, built and found.** Verified on scratch crates (cargo 1.99.1): `env!("CARGO_BIN_EXE_<bin>")` exists only for a bin of the **same package** as the integration test (a bin in another workspace crate: "may not be available for the current Cargo target"). The `cpd` package (`cli/`) owns all integration tests (`cli/tests/{engine,flow,pr,session,store,tooling,tui}`) and has `src/lib.rs`. So: model in `cli/src/fakes/tmux/` (lib module behind feature `fakes`), `[[bin]] name = "fake-tmux" path = "src/bin/fake-tmux.rs" required-features = ["fakes"]`, and `[dev-dependencies] cpd = { path = ".", features = ["fakes"] }`. Verified: `cargo build` (the quick check, the install `-p cpd --release`, `scripts/install-cpd.sh:76`) never builds it; `cargo test --no-run` builds it and sets `CARGO_BIN_EXE_fake-tmux`. `TestEnv::fake_tmux()` symlinks `env.bin()/tmux` to it (one symlink, no copy). The 7 in-crate tests that use `with_program` scripts (T-units:3) keep their own script: core, engine and tui unit tests cannot see another package's bin.

**State.** One SQLite file `$TMUX_TMPDIR/fake-tmux-<socket>.db` (rusqlite is allowed: bundled), one `BEGIN IMMEDIATE` per client call: calls from `cpd`, the engine and the test serialise as they do on a real server, and no daemon exists, so nothing can leak or outlive the test (the temp dir goes with it). Tables: `server` (exists?, options, hooks, bindings, buffers, env, version), `sessions` (id `$n`, name, env), `windows` (`@n`, session, name, layout order), `panes` (`%n`, window, argv, cwd, env, size, dead, dead_status, pid-less), `pane_options` (`@cpd_*`), `keys` (send-keys log per pane), `screen` (text a test seeds), `popups` (argv, client), `clients`. No process is ever started for a pane: a pane is a row. `kill-server` deletes the file, so the next `list-sessions` says `no server running on <path>` at once (the adapter's own loop, `tmux.rs:802-830`, then returns without its 50 ms sleep).

**Fidelity the adapter depends on (verified in `tmux.rs`).** Exit 1 = "no" for `has-session` (`:564-571`); stderr line `no server running on ` (`:955-960`); a missing `TMUX_TMPDIR` directory is refused by the adapter before tmux runs (`:521-531`), the fake checks it too; global flags `-u -L -f` and a `;`-chained argv (`new_session_args` `:992-1006` prefixes the 24 `SERVER_OPTIONS` of `:152-186`, so `;` must be parsed); `-P -F '#{window_id} #{pane_id}'` ids `@n`, `%n`; `display -p '#{pid}'` + `server_exe` (`:686`) needs a live pid: the fake prints `FAKE_TMUX_SERVER_PID`, which `TestEnv::command` sets to the test process's own pid (unverified: macOS `libproc` and Linux `/proc/<pid>/exe` then resolve to the test binary).

**Union of subcommands (35).** Product, verified by `rg 'strings\(&\["' core tui engine`: `list-sessions has-session new-session set set-environment show display display-message new-window split-window swap-pane rename-window respawn-pane(-k) kill-pane kill-window kill-server list-panes set-hook bind select-pane resize-pane list-clients display-popup set-buffer run-shell attach`. Tests add (`rg` over `cli/tests`): `capture-pane` (47 sites) `send-keys` (63) `list-windows` (11) `show-environment` `list-keys` `show-hooks` `show-buffer` `resize-window` `select-layout`. Options: `set -g|-s|-gq|-as|-p|-t`, `show -gv|-gqv`, `@cpd_session @cpd_title @cpd_view @cpd_job @cpd_history @cpd_machine @cpd_version @cpd_preview @cpd_workers*`, `remain-on-exit`, and `-t` forms `=name`, `=name:`, `%p`, `@w`, `=` (`tmux.rs:152-186`).
**Deliberately not modelled:** rendering. `capture-pane -p` returns the text a test seeded (`__ctl screen %3 'text'`), `send-keys` appends to the pane's key log, `display-popup` and `display-menu` record argv and client and return 0 at once (the adapter marks them INTERACTIVE with no deadline, `:40`), `attach` records the client and exits 0. `STATUS_FORMAT`, `BORDER_FORMAT` and pane geometry are tmux's to compute (class X, §2).
**Formats.** A small evaluator: `#{var}`, `#{@opt}`, `#{?c,a,b}`, `#{==:a,b}`, `#{!=:}`, `#{&&:}`, `#{||:}`, `#{!:}`, `#{n:}`, plus the variables the product reads (`rg -o '#\{[a-z_@A-Z]+'`: `pane_id window_id session_name session_id window_name pane_pid pane_dead pane_dead_status pane_index pane_width client_name client_width client_height client_activity version pid hook_window_name`). The `#{e|..}` arithmetic and `#{P/i/:}` loops of `STATUS_FORMAT` (`:301`) are stored, never evaluated.
**Hooks and `run-shell`, synchronously.** `set-hook -g` stores the command string. An event the fake itself causes fires the hook inside the same client call, before it returns: `__ctl pane-exit %3 --status 1` marks the pane dead and fires `pane-died` with the pane as target; `kill-window` and `kill-pane` fire `window-unlinked` with `hook_window_name`. A hook value is a tmux command string (`PANE_DIED_HOOK` `:129`, `WINDOW_UNLINKED_HOOK` `:139`): the fake runs a mini command interpreter for `if -F`, `run-shell [-b]`, `respawn-pane`, `select-pane`, `send-keys -M`, `;`. `run-shell -b` is run **in the foreground** with `sh -c`, the caller's `PATH` and the target's format-expanded command, and the call returns when it ends (so `cpd watch --ensure --wait` is the fake `cpd` of `fake_cpd_panes`, `common/mod.rs:1092`, deterministic). A hook that recurses into the fake is bounded by one nesting level (a second level is queued and drained before return). Bindings (`MouseDown1Status`) are stored; a test fires one with `__ctl click status <range>`.
**Control surface for tests.** `__ctl` (reachable only as the first argument, never produced by the product) and a Rust view `env.tmux_state()` (reads the SQLite file, no process): `panes()`, `pane_env(%3)`, `options()`, `keys(%3)`, `popups()`, `hooks()`. This replaces the 24 `new-session`/20 `capture-pane`/19 `list-panes` sites that today ask a real server.
**Pinned by its own tests, never against a real tmux (pro-d9).** About 110 tests: pure unit tests of the argv parser, target resolution, id allocation, the format evaluator, the hook interpreter, each subcommand's state change and each error text, written from tmux(1) as read plus the adapter's own expectations above (the adapter's tests are the contract: every `Tmux::*` method (`tmux.rs:576-870`) is run against the fake and its parse must succeed); and about 10 tests in `cli/tests/tooling/fake_tmux.rs` that exec the built bin (flags `-u -L -f`, exit codes, `no server running`, 8 concurrent calls under the transaction, hook order). Recorded real output may be pasted as a literal in a test but is never regenerated in the Gate.

## 4. Time

`core/src/clock.rs` today only formats timestamps (`:1-20`): there is **no `Clock`, no sleeper**, and the only seam is `host::limit::limit(name, default)` (`CPD_TEST_<NAME>=<seconds>`, debug build, `core/src/host/limit.rs:11-20`), which shortens a wait but still sleeps and polls. Seam: `trait Clock { fn now(&self) -> Instant; fn sleep(&self, Duration); }` in `core/src/clock.rs` (`SystemClock`; `ManualClock` in `cli/src/fakes`: `sleep` advances virtual time and returns at once, and records the call), passed as `&dyn Clock` at the loop entry, never a global. Three ways, by where the wait is:
1. **In-process loop** (unit and `cpd_core::*` tests): inject `ManualClock`; no sleep happens, the test asserts on the recorded naps and the virtual `now`.
2. **A `cpd` loop run by the binary** (`cpd watch`, `session run`, `driver`): the engine's loop is `Engine::tick()` (`engine/src/watch/engine.rs:117`) plus a nap loop (`:399-414`, `NAP` `:39`); extract `Engine::run(clock, until)` so tests drive N ticks in process on fake tmux/gh (`Tmux::with_program`), and keep one binary-level test of the flag wiring.
3. **A test waits on an event, not a poll**: `Beacon` in `cli/tests/common`: a FIFO the shims (`fake gh`, fake `cpd`, fake pi, the fake tmux's `__ctl`) write one line to per event, and `Beacon::wait(n)` blocks in `nix::poll` (feature `poll` is in the workspace, `Cargo.toml:16`) with the nextest limit as its only deadline: a kernel wake-up, no loop, no sleep. It replaces `wait_until`/`poll`/`wait_screen`/`wait_whole_ticks` (`common/mod.rs:396-510`, `:1147`); the sleeps in `TestEnv` teardown (`:186`) and the reaper's `sleep 1` loop (`:249-260`) are our own shim and stay (allowed, reaped).

## 5. The guard (ratchet)

Follows T-pi §2.3. **Tripwire.** `scripts/tripwire/tmux` (sh, no `timeout`, passes `check-portable.sh:104-151`; add `tripwire/tmux` to `covered`, `:17`). It is first on `PATH` for the **last segment** of `verify:steps` only (`package.json:15`: `PATH="$PWD/scripts/tripwire:$PATH" scripts/cargo.sh nextest run --workspace`), so `npm test`, `pi-check.sh` and the build never see it. A test's fake `tmux` in `env.bin()` still wins (`common/mod.rs:854-856`). It reads `NEXTEST_BINARY_ID` and `NEXTEST_TEST_NAME` (set by nextest 0.9.148, already relied on by `gate-run.sh:132,134`); when the pair matches `scripts/tripwire/allow.txt` it `exec`s the real tmux (found after removing its own dir from `PATH`; `# portable: forwards the caller's argv`), else it prints `tripwire: real tmux called by <id> <name>`, appends to `$TMPDIR/tripwire.log` and exits 127. A test that swallows the failure still fails the run: `gate-run.sh` `finish()` prints the log and fails if it is non-empty (after `:121`, before `rm -rf "$RUN"` `:141`). `real_tmux()` (`common/mod.rs:1273`, 19 sites) returns the first `tmux` on PATH, so those tests are the first entries. The change edits three places that pin the Gate string: `package.json:15`, `pi/test/gate.test.ts:12-24`, `docs/implementing.md:171`.
**Allowlist `scripts/tripwire/allow.txt`.** One line per debt: `<binary_id> <test-name-prefix>  # <PR key>: <reason>`, e.g. `cpd::tui bare::  # m-tui-t2: cockpit build on a real server`. Prefix match on `NEXTEST_TEST_NAME` (a file is a module, `cpd::<area>` is the binary, `.config/nextest.toml:11-14`). The tag after `#` must be a PR key of §7 (a node test in `gd-trip` refuses an entry without one). **Generated from the audit**, not by running the suite: `gd-trip` writes it from the inventories' per-file classes at file granularity (every file with class T or X, `T-*` §1 tables: about 60 prefixes), an over-approximation that is safe; plus per-test lines for mixed files. A node test pins that each prefix matches at least one name of `cargo nextest list --workspace` (a renamed test drops out silently otherwise, `nextest.toml:41-56`). Real git contract tests (§3) are permanent `contract::` lines. The `tmux-restart` test group (`nextest.toml:71-80`) lists the same filters: its lines go in the same migration.
**An area PR removes its lines**: the PR's migration Jobs delete the prefixes tagged with its key; the tripwire then fails any test of that area that still reaches real tmux. The count of lines per tag is the ratchet: a line cannot be added (the node test refuses an untagged or new-tag line).
**The last PR (`del`)** deletes `allow.txt` and the match; the tripwire stays as an unconditional deny (a permanent guard, 6 lines), and `real_tmux()` and the `tmux-restart` group go.
**Static sleep check.** TypeScript: extend `pi/test/no-fixed-sleeps.test.ts:7-15` (runs in `npm test`, no Gate edit) to refuse `setTimeout(`, `setInterval(`, `Date.now()` deadlines, `spawnSync("sleep"` and `waitFor` outside `fake.ts`, with an allowlist of `file:line` debts (T-pi: `compact-tools.test.ts:705-718`, `editor-box.test.ts:209`, `slack-channel.test.ts:99`, `follower.test.ts:34,72`, `handle.test.ts:13`, `pi-check.test.ts:315`). Rust: a node test in the same file that scans `cli/tests` and test modules for `thread::sleep|Instant::now`, with the same tagged allowlist; a new script would need `gate.test.ts`, `implementing.md:171` and `check-portable.sh:17` (T-pi §2.4), so the node test is cheaper (DRY). Shim text (`sleep 60` inside a fake body) is not checked: reaped processes are allowed (`leak-timeout` 100 ms fails a leak, `nextest.toml:24`).
