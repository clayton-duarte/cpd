## 0. What the scope does, in one paragraph

No test of the scope starts a tmux pane or server: no `new-session`/`new-window`/`TestEnv::tmux`/`start_*`/`bare::` appears in the 8 files (`rg tmux` finds only config lines `[tmux] socket = <env.tmux_socket()>`, e.g. merge.rs:128, pr_cleanup.rs:86, pr_push.rs:50, pr_start.rs:37, and the stub `tools/tmux` at git_guard.rs:149). The real `tmux` *binary* is still **executed** (list-panes, no server running) by product code reached from the tests: `core/src/merge/recover.rs:153` -> `core/src/driver/worker.rs:385` (`kill_attempt_window`: `list_panes`, then `kill_window` only if a window matches) and `core/src/pr/poll.rs:531-540` (`clean_up`: `list_panes`, `kill_window`). `TestEnv::new` denies gh/pi/curl/wget/ssh with shims (common/mod.rs:305, 749) but **not tmux nor git**, and the test `PATH` is the process's own (`inherited_path`, common/mod.rs:299). `Tmux::list_panes` returns an empty list when tmux says no server runs (core/src/host/tmux.rs:869-875), so no server is started and nothing is killed; with a real tmux the answer comes from the User's `TMUX_TMPDIR` in the in-process tests (they do not use `TestEnv::command`, whose env sets `TMUX_TMPDIR`, common/mod.rs:861) - `unverified` at run time. Real git is the dominant external. Matches of `rg -c 'Command::new\("git"\)|git_repo|local_origin|\bgit\('` per file: git.rs 128, merge.rs 86, pr_start.rs 60, pr_cleanup.rs 46, pr_push.rs 39, pr_cleanup_cancel.rs 13 (an upper bound: includes the helper definitions).

Two ways the product reaches git, both through ONE function: `core/src/git/run.rs:run` (`Command::new("git")`, run.rs:57; `ok`, `fetch`, `worktree_add`, `retry_transient` wrap it). The in-process tests (git.rs, merge.rs, the fixtures of pr_*.rs) call `cpd_core::*` directly in the test process: their git does **not** run in `TestEnv::command`'s env (no `GIT_CONFIG_GLOBAL`, no process group; see comments git.rs:318 and merge.rs:111). The binary-driven tests (`env.cpd(...)`, `cpd watch`) go through `TestEnv::command`.

## 4. Leak and flake risks

1. **Child that outlives the test.** git.rs:662 (`sleep 10`), 672 (`sleep 30`), 1348 (alias `sleep 120`) rely on our process-group kill; if the kill is wrong the sleeper lives 10-120 s. The reaper/teardown kills the env's group (common/mod.rs:774-787), but in-process `cpd_core` calls (git.rs, merge.rs) do not use `TestEnv::command`, so their git children are not in that group: a test process killed mid-call leaves git (<= 60 s local, 300 s network, run.rs:16-20) - `unverified` at run time.
2. **Real processes killed on drop.** `Child::drop` kills only `cpd pr push` (pr_cleanup.rs:602-618, pr_push.rs:200-216) and `Engine::drop` only `cpd watch` (pr_start.rs:236-241): the Gate hook (<= 60 s `sleep 0.1` loop) and an engine's `cpd pr poll` child live until the env teardown kills the group. A `SIGKILL` of the test binary leaves `cpd watch` holding the watch lock - `unverified`.
3. **FIFO holds a real git in `open(2)`.** `answer_reads` (common/mod.rs:457-501) blocks git until the answering thread opens the FIFO; if that thread dies, `run()` waits for git's 60 s local deadline (run.rs:16). git.rs:1389-1462.
4. **Wall-clock assertions under load average 40-120 (pro).** git.rs:337 asserts a failing `fetch` (a real git) returns in under 1 s; 1354 asserts the 1 s deadline call returns in under 4 s; 296 / 1120 / 1250-1251 depend on 1 s `thread::sleep` vs a lock wait; `wait_until` is 30 s (common/mod.rs:388) and 120 s at pr_cleanup.rs:633-635, pr_push.rs:232-234; `GitWrapper::run` 10 s (common/mod.rs:560); the engine tests count real 0.1 s ticks (pr_start.rs:631-866). git.rs:518's slow command (`sleep 0.3` after both failures) and 495's 2 s poll are ordering by time.
5. **Vacuous pass on macOS.** git.rs:1325 `running(pid)` reads `/proc/<pid>/stat`, absent on macOS, so `!running(pid)` is true at once: the 1348 sleeper test checks nothing of the group kill there (`unverified` on a Mac; the code says `is_ok_and`, so a missing file is "not running"). Likewise `is_dead` (git.rs:652) uses `ps`, which exists, so 659/671 are real.
6. **Not hermetic.** In-process git/tmux use the User's global git config and `TMUX_TMPDIR` (comments git.rs:318, merge.rs:111; `identify` merge.rs:113 patches identity per repo). A User with `commit.gpgsign`, hooks, `gc`, `rerere` or `pull.rebase` in `~/.gitconfig` changes results; `unverified` on pro.
7. **Platform branches in assertions.** `strerror_zero()` (git.rs:1223), Apple git reading `commondir` twice (git.rs:1442-1446): tests that encode git version/OS behaviour.
8. **Load of real git.** 128+86+60+46+39 git helper calls per run of the scope; git.rs:1287 alone 640 `worktree add` + 640 `remove`; pr_start.rs:471 8 parallel starts; each `git_repo` copies a template and runs `update-index --refresh`.
9. **Real timers in product code that tests wait out.** Retry sleeps 100-500 ms (run.rs:111-112, lead.rs:141-142; up to 19 in git.rs:1434, about 6 s), `KILL_PAUSE` 1 s (worker.rs:353) if a window cannot be killed (reachable only with a real tmux server: not in these tests), `LOCK_TIMEOUTS` 10 s.
10. **Shared files across test processes.** `git_repo_template` and `store_template` are shared under `CARGO_TARGET_TMPDIR` and moved into place by `rename` (common/mod.rs:972-990): atomic, so not a flake, but a stale template after a git upgrade is possible (unverified).
11. **Teardown needs real `sqlite3`, `ps`, `tmux`** (common/mod.rs:664, TEARDOWN_SH): a missing tool fails every test at the first `TestEnv::empty` (a panic at common/mod.rs:670).
