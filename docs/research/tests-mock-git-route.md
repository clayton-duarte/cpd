# tests-mock git route: what the product asks of git, what a fake must model, the plan of PR `port-git` (Job `dz-git`, attempt `dz-git-a1`)

Docs only; nothing was run but `rg` and reads. **verified** = read in the source at the path named; `unverified` / `guess:` = inferred. Paths are from this worktree (base 66aefbee: it has no `Clock`, no `Runner`, no `fakes` module in `core`; what the Spec says of PR `clk` and `port-run` is taken from the Spec, `unverified` here). Decisions this follows: one process trait `Runner`, tmux and git are routes of its fake (Lead, 2026-10-25); policy [tests] (no real git in a test, no sleep, no leak).

## 1. The product's git surface

**The two spawn points.** Every git call of the product is `core/src/git/run.rs::run`: `Command::new("git")`, argv `git -C <dir> <args>`, `GIT_TERMINAL_PROMPT=0`, `GIT_CONFIG_COUNT=2` with `core.filesRefLockTimeout=10000` and `core.packedRefsTimeout=10000` (`LOCK_TIMEOUTS`), stdin null, deadline 60 s (300 s for `fetch`, `push`, `ls-remote`), through `host::deadline::output(…, "git", …)`. **One more spawn bypasses it:** `core/src/context/distill.rs:434` (`Command::new("git").args(["-C", repo, "grep", "-l", "-w", <record id>, "--", "docs", "*.md"]).output()`, no deadline, exit 1 = no match), so it is **not** one of the nine `deadline::output` callers of PR `port-run` and needs its own Job (§6 `git-grep`). A third form has no `-C`: `engine/src/doctor/tools.rs:23` runs `git --version` (output parsed as `git version 2.43.0`, minimum 2.43.0; it is one of the nine callers). `core/src/policy/origin.rs:108` is a `#[cfg(test)]` fixture (`git init`), not product.
**Error mapping (`run.rs`).** `run` returns `Out {code, stdout, stderr}` for any exit; only a git that cannot start or dies by signal is `git_failed` (details `argv`, `exit`, `stderr` = last 60 lines), a deadline is `tool_timeout`. `ok` maps any non-zero exit to `git_failed`. `fetch` / `worktree_list` / `worktree_add` retry (20 rounds, 100–500 ms `thread::sleep`, `retry_transient`) while stderr contains `bad object worktrees/` (`is_fetch_race`) or `fatal: failed to read …worktrees/…/commondir: Success|Undefined error: 0|No such file or directory` (`is_admin_dir_race`); a fake never emits those, so the retry is tested with scripted `FakeRunner` replies and a virtual clock (the real `sleep` at `run.rs:~124` needs `Clock`).
**Global options the product puts before the subcommand:** `-C <dir>` (always); `-c core.editor=true -c sequence.editor=true` (`pr/rebase.rs` `NO_EDITOR`, rebase and `--continue` in the Lead worktree); `--no-optional-locks` (`git/lead.rs::round` `diff --quiet`, `git/worktree.rs::remove_merged_lead` `status`).

## 3. The model

**What `docs/research/tests-mock-design.md` §3 assumed** (superseded by the Lead decision and ADR 0013 where they differ): Option A, a stateful `fake-git` **binary** on `PATH` with state in **SQLite** (commits as id/parents/tree map, refs, remotes pointing at another model file, worktrees as dirs), reached by built `cpd` processes through `CPD_TEST_GIT`; **23 subcommands** + about 12 fixture ones (`rg` there; confirmed above: rev-parse remote config symbolic-ref ls-remote fetch push merge-tree merge-base update-ref rebase diff status cat-file rev-list ls-tree write-tree read-tree log worktree branch grep, plus `--version`); about **170 new tests in 5 Jobs** (`fg-spike`, `fg-read`, `fg-merge`, `fg-wt`, `fg-env`) at about 35 each; abort criterion: `merge-tree` + `rebase` over 3 Jobs; about 12 real contract tests. What changes now: the fake is **in-process** (a route of `FakeRunner`), so there is no second process, no SQLite and no cross-process locking: the state is one `Arc<Mutex<Universe>>` (the mutex stands for git's ref lock). A test that still spawns the built `cpd` cannot see it (the 2 e2e tests, the scripts of §2).

**Universe** (`core/src/fakes/git/`, feature `fakes`): all pure data, deterministic, no wall time.
- *Objects*, one arena for all repos: `Blob(bytes)`, `Tree` = **flat** sorted map `path → (blob, mode)` (no nested trees: `ls-tree -r`, `diff`, `merge` are per-path; a tree id = sha1 of its canonical text), `Commit {tree, parents, author, message, time}` (id = sha1 of the canonical text; `time` from the injected `Clock`, author from the global config `user.*`). Per repo a `have: HashSet<Oid>`: `cat-file -e`, `(fetch first)` and `Push::Contained`'s "known" test need *which repo holds which object* (`worktree.rs::push_commit`, `pr/rebase.rs::remote_contains`); `fetch`/`push` copy the closure.
- *Repo*: `{ main worktree path, bare?, refs: BTreeMap<String, Oid> (refs/heads, refs/remotes, refs/tags), HEAD per worktree (symbolic branch | detached oid), reflogs: ref → [(old, new, tree, message)] (rule S's `log -g` reads trees from them; `update-ref -m`, commits, rebase append), config (multi-valued: `remote.origin.url`, `remote.origin.fetch`, `url.<x>.insteadOf`, `user.*`), worktrees: [{path, id, head, locked reason, index: path → (blob, stage 0–3), rebase state}] }`. A remote is a config URL resolved (after `insteadOf`, as `local_origin` sets) to another repo of the Universe by path; a URL that resolves to none (the `https://github.com/acme/<x>.git` of `keyed_repo`) fails `fetch`/`push`/`ls-remote` at once with exit 128 `fatal: unable to access '<url>': Could not resolve host` (guess: no test reads that text; real git there waits on DNS).
- *Revisions* (`rev.rs`): `HEAD`, a full sha, refs with git's DWIM order (`<x>`, `refs/<x>`, `refs/tags/<x>`, `refs/heads/<x>`, `refs/remotes/<x>`), `<rev>^{commit}`, `<rev>^{tree}`, `<rev>:<path>`, `a..b`, `a...b`. The product uses no `~`/`^N` (`rg` of `core/src`, only `^{commit|tree}`; `unverified` for tests: not counted).
- *Algorithms*: LCA of two commits (BFS; criss-cross = take the first, `unverified` that no test has one); `is-ancestor`; `rev-list` with `--not`, `--remotes=origin`, `--no-merges`, `--count`; **text three-way merge** (line diff by LCS between base and each side, hunks that do not overlap merge, overlapping ones conflict) per path with the cases both-modified, add/add (`api.txt` in `cli/tests/pr/pr.rs:861`), modify/delete, delete/delete, mode ignored; **no rename detection** (real git has it in `merge-tree`/`rebase`: `unverified` whether any test renames a file under a conflict; `mv` is used twice); conflict text `<<<<<<< <ours label>` / `=======` / `>>>>>>> <theirs label>`; `merge-tree --write-tree --name-only`: line 1 = tree id (of the tree with markers, stored as objects), then conflicted paths sorted, blank line, `Auto-merging …` / `CONFLICT (content): Merge conflict in <p>` messages; `rebase <onto>`: replay `onto..HEAD` non-merge commits by the same three-way (base = parent tree), fast-forward when HEAD is an ancestor of `onto`, "up to date" exit 0 when `onto` is contained; on a conflict stop with the stages in the index, markers in the file, HEAD detached at the last applied commit, exit 1 `CONFLICT … Could not apply <sha>`; `--continue` commits the index (stage 0 only, else exit 1 `Committing is not possible because you have unmerged files`) with the original author/message and goes on, then moves `refs/heads/<b>` and re-attaches HEAD; `--abort` restores `orig-head`, index and files. Patch-id dedup of already-applied commits: not modelled (`unverified` that tests need it).
- *What a test sees on disk* (the product and the tests read these; verified in §1/§2): a **repo** = `<dir>/.git/` (a real empty directory plus `.git/worktrees/<id>/` for linked ones) and the working-tree files, **real files in a temp dir** (tests `fs::write` `README.md`, hooks run `sh -c` with that cwd); a **linked worktree** = a directory with a **`.git` file** (`gitdir: <repo>/.git/worktrees/<id>`); a stopped rebase = `<gitdir>/rebase-merge/` with an `orig-head` file, the path `rev-parse --git-path` prints; `index` = a real file in the git dir rewritten (rename) on every index change so `Probe` sees a new inode, and `index.lock` is a file a test can create to make a round `Busy` (`git/lead.rs`). Everything else (objects, refs, packed-refs, config) lives only in the Universe: no `.git/objects`, `.git/refs` or `.git/config` file exists. Checked with `rg '\.git/' cli/tests core/tests`: tests touch the git dir only at `pr/git.rs:255` (`.git/refs/remotes/origin/main.lock`), `:911`, `:981` (`.git/worktrees/<id>/…`), `:1068` (byte-compare of `.git/config`) — all four are the real-only race / no-config-write tests of §5 — and `flow/driver.rs:588` (writes `.git/hooks/post-rewrite`, which **git itself** runs after a rebase: not modelled, that one test needs a scripted `rebase` reply that runs the hook, or stays real); `pr/pr_start.rs:251` reads `config --get-regexp ^branch\.` through git (the route must serve `config --get-regexp`). Paths printed by `worktree list --porcelain` are the **canonical** ones (macOS `/var` → `/private/var`; the product's `real()` in `worktree.rs` exists because real git prints them: `unverified`).
- *Fidelity points a test depends on* (each needs a test in the Job that owns it): `rev-parse --verify --quiet` 1 vs `--verify` 128 `fatal: Needed a single revision`; `symbolic-ref -q HEAD` 1 when detached; `ls-remote --exit-code` 2; `merge-base --is-ancestor` 0/1, 128 on an unknown object; `update-ref` CAS miss exit 128 `cannot lock ref`; `branch -d` of an unmerged branch exit 1 `not fully merged`, of a branch checked out in a worktree exit 1; `worktree add` onto an existing non-empty path or a taken branch exit 128; `worktree remove` of a dirty tree without `--force`, of a locked one without `--force --force`; push rejection porcelain line `!\t<from>:<to>\t[rejected] (non-fast-forward)` vs `(fetch first)` when the remote tip is not in the local `have`; `=` for up to date, `*` new branch; `--force-with-lease` stale = `! … (stale info)`, but a push of what the remote already has succeeds whatever the lease (`pr/rebase.rs::last_seen` comment, git 2.43); `status --porcelain` collapses an untracked directory to `?? dir/` (guess: tests assert on it rarely; implement) and honours literal `.gitignore` lines only (else unsupported).

## 4. The route

`GitRoute { universe: Arc<Mutex<Universe>>, clock: Arc<dyn Clock>, unsupported: Mutex<Vec<String>> }` is a `Handler` registered on the program name `git` in `FakeRunner` (shape of `Handler` is PR `port-run`'s: `unverified` here; the route needs the argv, the env, the cwd and returns exit code + stdout + stderr and virtual elapsed time 0).
1. **Global options**: `-C <dir>` (repeatable, relative to the previous or to the request cwd), `-c <k>=<v>` (accept `core.editor`, `sequence.editor`, `core.quotePath`, `core.filesRefLockTimeout`, `core.packedRefsTimeout`, `user.*`; any other key unsupported), `--no-optional-locks`, and `GIT_CONFIG_COUNT/KEY/VALUE`, `GIT_CONFIG_GLOBAL` from the request env; no `-C` = the request's cwd (the tests' `env.git(dir, …)` runs with cwd, §2). `git --version` (no subcommand) prints `git version 2.43.0` (the minimum of `doctor/tools.rs`).
2. **Repo resolution**: the nearest ancestor of the directory that is a registered worktree path; none → exit 128 `fatal: not a git repository (or any of the parent directories): .git` (`pr/add.rs::main_worktree` needs it).
3. **Dispatch**: a table `subcommand → fn(&mut Universe, &Ctx, &[String]) -> Out`, each with a strict argument parser: a flag it does not list is `fake-git: unsupported: <subcommand> <flag>` and an unknown subcommand `fake-git: unsupported: <subcommand>`, **both exit 1 on stderr** (the spec's rule). Exit 1 is also a real answer (`--quiet` miss, `is-ancestor` no, detached), so the route **also records every unsupported hit** in `unsupported`, and the testkit fails the test at drop if the list is not empty (fail loud; no test can read it as "no").
4. **Order of precedence in `FakeRunner`**: scripted replies first (a test that wants `bad object worktrees/` for the retry loops, a timeout, exit 128 of a deadline), then the `git` route, then "no route for `<program>`" as an error. The route never sleeps; the retry loops of `run.rs` sleep on the `Clock`.
5. **Fixture API next to the route** (`Repo` handle: `write(path, text)`, `commit(msg)`, `branch`, `push`, `bare_origin()`, `keyed()`), backed by the same functions the subcommands call; `env.git(dir, args)` of the testkit keeps its signature and goes through the route, so the ~900 call sites migrate without churn (`mig-*` replace `git_repo` with the handle). The test-only subcommands of §2 (`init add commit clone switch checkout reset merge tag mv rm show for-each-ref diff-index diff-files update-index`, writing `config`/`remote`/`branch`) are served by the same table but in their own Job, after the product ones.
6. **Files the route writes** (on disk, in the temp dir of the test): the working-tree files, `.git/` dir, `.git` file of a linked worktree, `.git/worktrees/<id>/{index,rebase-merge/…}`; nothing else, nothing outside the worktree's temp root, no process, no socket: no leak by construction.
