## Leaks

### Bug 3 — 32 `tmux -L cpdt-*` servers, each with one dead `cpd watch` pane (the most common leak)

- **Who creates it.** One test: `cli/tests/tui/tui.rs:477` `tui::a_failing_action_prints_nothing_exits_0_and_tells_the_client`. All 32 servers on hs carry `NEXTEST_TEST_NAME=tui::a_failing_action_prints_nothing_exits_0_and_tells_the_client` in `/proc/<pid>/environ` (binary `cpd::tui` or the older `cpd::it`), `TMUX_TMPDIR=/dev/shm/cpd-test-<x>/tmux`, cwd `/dev/shm/cpd-test-<x>/home (deleted)`. The test starts the cockpit (`env.cpd(&["tui"])`, which also runs `watch --ensure`, `tui/src/cockpit.rs:67`) and then kills the server itself, `cli/tests/tui/tui.rs:498` (`tmux_out(&env, &["kill-server"])`), to test "no tmux server at all". `cli/tests/flow/plan.rs:530` and `cli/tests/engine/watch.rs:647` kill the server the same way (unverified that they leak: they were not in the 32).
- **Exact path by which it escapes teardown.** cpd arms two supervising hooks on every server it starts, `pane-died` and `window-unlinked`, each running `cpd watch --ensure --wait` in a `run-shell -b` (`core/src/host/tmux.rs:100-128`, `:163-164`, contract §6.6). A `kill-server` sometimes runs the hook before the server is gone; the `run-shell` child is a child of the dying server, not of the test's process group, and `ensure` starts a **new** server for the same socket name. Then:
  1. `TEARDOWN_SH` (`cli/tests/common/mod.rs:139-150`, `stop_tmux`) looks for the socket only at `$dir/tmux/*/$socket` and returns when it is not there; the env dir is removed (`rm -rf "$dir"`).
  2. The late `ensure` runs when `$dir/tmux` is already gone. tmux does not fail for a `TMUX_TMPDIR` that does not exist: it falls back to `/tmp/tmux-<uid>/` (verified: `TMUX_TMPDIR=/dev/shm/audit-a1-nonexist tmux -L x new-session -d "sleep 30"` left `/tmp/tmux-1000/x`). So the new server's socket is in `/tmp/tmux-1000/cpdt-<pid>-0`, where no teardown looks.
  3. The server has `exit-empty off` and `remain-on-exit on` (`core/src/host/tmux.rs:165`, `SERVER_OPTIONS`), and its one pane (`cpd watch`) is dead (`cpd` has no `CPD_HOME`), so it never exits: 0 CPU, 3.6 MiB, for ever. `ss -xlp` on hs maps `/tmp/tmux-1000/cpdt-848281-0` to the server pid.
  4. The late `cpd` also recreates `$dir/cpd-home/run/watch.log` and `locks/` (`engine/src/watch/log.rs:24`, `engine/src/watch/ensure.rs:155`: `create_dir_all`), which is why every `/dev/shm/cpd-test-*` left on hs holds only `cpd-home/` (cause of the 46 dirs of bug 5).
  The `watch.log` of a leaked home says `supervision: ...` (the hook's `ensure`), e.g. `cpd watch: supervision: cannot start the engine: The engine did not start in pane %0: it exited with status 1`.
- **Reproduced.** R3a: 5 of 40 runs of the test leaked a server (`ps`: ppid 1, `CARGO_MANIFEST_DIR` = my worktree, socket in `/tmp/tmux-1000`, pane `cpd-work:watch dead=1`) and 6 of 40 left a `/dev/shm/cpd-test-*` dir. R3b (no cargo, real `cpd`): 1 of 40 iterations left a server whose `watch.log` ends `supervision: the engine runs`, socket in `/tmp/tmux-1000`. A single run is mostly clean, hence 1–12 % per run. `kill-window` of the engine's window fires the hook reliably; `kill-server` only sometimes (my plain-tmux probe with a `touch` hook: 0 of 2).
- **Not the cause:** the reaper and `TestEnv::drop` (`cli/tests/tooling/harness.rs` `a_killed_test_leaves_no_tmux_server_process_dir_or_reaper` and `a_dropped_env_...` pass today: `2 passed`).

## The Gate leak check

Decided (hs-d519, hs-d39): the Gate notes what its own test run creates and fails when any is left at the end; nothing hunts machine-wide.

**Where it runs.** A new `scripts/gate-run.sh '<command…>'`, and `package.json`'s `verify` becomes `scripts/gate-run.sh npm run verify:steps` (the present chain moves unchanged to `verify:steps`). The Gate's pre-merge hook (`.config/wt.toml`, protected, unchanged) already runs `npm run verify`, so the check runs in every Gate and in `npm run verify` by hand, once, after the last step. No other hook.

**How a run's own leftovers are told from other runs'.** One random run id, made by the script and inherited by everything the run starts:

1. `RUN=$(mktemp -d "${TMPDIR:-/dev/shm}/gate-run.XXXXXX")`; `GATE_RUN=${RUN##*.}` (6 random characters); `export GATE_RUN TMPDIR=$RUN`. Everything below is keyed on that id, so another Worker's concurrent Gate (a different id, a different `$RUN`) can never match.
2. **Directories.** `TMPDIR=$RUN` is honoured by `tempfile::tempdir()`, `mktemp` and `scripts/pi-check.sh`; `ENVS_DIR` in `cli/tests/common/mod.rs:201` becomes `$TMPDIR` when set (else `/dev/shm` as today). At the end, anything under `$RUN` is a leftover (each test removes its own).
3. **Processes** (including detached, `setsid`-ed and tmux servers, which no process group reaches). At the end the script scans `/proc/[0-9]*/environ` of its own uid for the exact entry `GATE_RUN=<id>` and excludes itself and its own ancestors. The variable survives `TestEnv::command` (it strips only `CPD_ PI_ GIT_ XDG_ PLANNOTATOR_ GH_ GITHUB_ SSH_`, proxies, `TMUX`, `TMUX_PANE`: `cli/tests/common/mod.rs:646-650`), nextest, and a tmux server (it inherits the starter's environment: the 32 leaked servers still hold `NEXTEST_RUN_ID`). It does not survive `env -i` / `env_clear()`: `scripts/pi-check.sh` adds `GATE_RUN` to its allow-list (`:61`), and the `env_clear()` callers (`cli/tests/tooling/{slot,cargo_script,npm_fresh,preview_script}.rs`, `cli/tests/pr/git_guard.rs:66`) run short scripts whose children keep their own `$RUN` paths (directory check). On macOS there is no `/proc`: `ps -axww -E -o pid=,command=` prints the environment (unverified, not run on `mac-air`); the rule is the same.
4. **tmux sockets.** Every socket the run creates carries the id: `TestEnv` names it `cpdt-$GATE_RUN-<pid>-<n>` (today `cpdt-<pid>-<n>`, `cli/tests/common/mod.rs:549`) and `pi-check.sh` `pi-check-$GATE_RUN-$$` (today `pi-check-$$`, `:55`). The check lists `/tmp/tmux-<uid>/*-$GATE_RUN-*` and `$RUN/**` for socket files. (A hook-restarted server lands in `/tmp/tmux-<uid>/` when `TMUX_TMPDIR` is gone, bug 3, and is found here and by its environment.) A socket of a dead server that the run's tests created is also a leftover (tmux does not unlink it).

**What it prints on failure** (stderr, then exit 1; the hook's `|| exit 64` turns it into the Gate failure; a failing command's own status is returned unchanged and the check still runs and prints, so a red run's leaks are named too):

```
gate-run: FAIL: this run (GATE_RUN=aB3dE9) left 3 things behind:
  process 912233 (ppid 1) tmux -u -L cpdt-aB3dE9-848281-0 -f /dev/null set -g mouse on …
  process 912301 (ppid 912233) cpd watch
  socket  /tmp/tmux-1000/cpdt-aB3dE9-848281-0
  path    /dev/shm/gate-run.aB3dE9/cpd-test-JhabOP
gate-run: the test that left them: grep the id in the process environment (NEXTEST_TEST_NAME), e.g. `tr '\0' '\n' </proc/912233/environ | grep NEXTEST_TEST_NAME`
gate-run: stopped 2 process(es) and removed 2 path(s) of this run (nothing else was touched)
```

It then SIGKILLs only the pids it listed, removes only the listed sockets and `$RUN`, so the failure itself leaks nothing; a clean run prints nothing and removes the empty `$RUN`.

**Not in this check:** a count of the machine's sockets, `/tmp` or `ps` (other runs would fail it); `/tmp/.tmp*` of a *killed* Gate (the Gate is dead, nobody runs the check; its `$RUN` is the one place to sweep, and Job audit-sweep deletes today's).
