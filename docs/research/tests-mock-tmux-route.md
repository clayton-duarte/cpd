# tests-mock: the tmux route (research for PR port-tmux)

Job `dz-tmux`, Attempt 1. Every claim names the file and function it was read from (`rg`, `read`, on this worktree); a claim that is not read is marked `unverified`. Nothing was run against a real tmux. `Runner`, `FakeRunner`, `Handler` and `Call` do not exist yet (port-run) and `Clock`/`ManualClock` are in the Lead branch cpd/tests-mock/clk, not on this one (`core/src/clock.rs` here holds `timestamp`/`now` only), so their shapes below are taken from the Job's Context and are `unverified`.

## 1. The product's tmux surface

**One spawn site.** `core/src/host/tmux.rs` says it is the only place that spawns tmux (module doc). Every call is `tmux -u -L <socket> -f /dev/null <args>` (`Tmux::argv`), built by `Tmux::command` from `client()` (`-u`, env `TMUX`, `TMUX_PANE`, `CPD_SESSION`, `CPD_ATTEMPT` removed, stdin null), plus `TMUX_TMPDIR` when `Tmux::with_tmpdir` set it. `Tmux::output` runs it with `deadline::output(.., "tmux", 10 s)`, except `display-popup` (`INTERACTIVE`, `deadline_of`): `cmd.process_group(0).output()`, no deadline. Before the spawn `Tmux::output` refuses a `TMUX_TMPDIR` (own, else the process's) that is not a directory (`std::path::Path::is_dir`, real fs, `tmux_failed`). Exit codes: `run` fails on non-zero (`tmux_failed`, last 60 stderr lines); `check` reads 0/1 as yes/no.

## 3. The route

**Entry.** `fakes::tmux::run(&Invocation { argv, tmux_tmpdir, cwd, env })` takes everything after `tmux`, including `-u -L <s> -f /dev/null`. `Tmux::command` already builds exactly that (`argv[1..]`), so a `Handler` for program `tmux` maps `Call` to `Invocation`: `argv = call.args`; `tmux_tmpdir` = the `TMUX_TMPDIR` entry of `call.envs`; `cwd = call.cwd` (else the runner's cwd, `unverified`); `env = call.envs`. Missing or empty `TMUX_TMPDIR` is exit 1 with stderr `error creating /tmp/tmux-<uid> (TMUX_TMPDIR is not set)` and no stdout (`cli/src/bin/fake-tmux.rs`, `main`): the route copies that text; `Outcome { code, stdout, stderr }` becomes the `Runner`'s output. `call.envs` must carry the removed variables (`TMUX`, `TMUX_PANE`, `CPD_SESSION`, `CPD_ATTEMPT`) as removals so the test for `client()` (tmux.rs `client_strips_cpd_session_and_cpd_attempt`) can read them from the call record: whether `Call.envs` can hold a removal is `unverified`; if it cannot, port-run must add it.

**Program names.** The route is registered under `tmux`. `Tmux::with_program(path)` runs another program: the route must match on the file name too (`unverified` whether `Handler` routes by basename), or `with_program` is dropped in the tests that use it (8 users by `rg 'with_program('`: core tmux.rs ×2, engine `workers/no_inbox.rs`, tui `dialog/tests.rs` and `select_tests.rs`, session/host.rs ×3; all but core :1316 write a shell script).

**`-V` and wrappers.** G1: the route answers `-u -V` itself before `run_commands`, `tmux 3.6a` (the fake's `#{version}` is `3.6a`, `variable`), and `installed_version()`/`run_tool` must go through the `Runner` (they are the only spawns that bypass `Tmux`). The `env.fake("tmux", …)` calls (18 single-line sites by `rg`: session/host.rs ×3, session.rs ×2, engine/doctor.rs ×2, watch.rs ×2, install_script.rs ×2, harness.rs ×2, plan.rs, tui.rs, tui_merge.rs, bare.rs, tui_plan.rs; and about as many in the multi-line `"tmux",` form, `unverified`), most of which `exec` the real tmux after a `case` on argv, become a decorator `Handler` in front of the route: a list of (argv matcher, scripted reply) tried first, the route behind, and the `Call` record the FakeRunner already keeps replaces `env.calls("tmux")`.

**Nested processes.** The only place the fake starts a real process is `hooks::run_shell` (`Command::new("/bin/sh").arg("-c").arg(cmd)`, `current_dir(inv.cwd)`, `env_clear().envs(inv.env)`, stdin/stdout/stderr null, `.status()`), reached by `run-shell [-b]` from a call, a hook (`pane-died`, `window-unlinked`, `fire`) or a binding (`__ctl click`). `if -F` and every other hook command are interpreted in-process (`hooks::run_string` → `dispatch`). The route is built with `Arc<dyn Runner>` (`unverified` name) and `run_shell` calls it with `Call { program: "/bin/sh", args: ["-c", <cmd>], cwd: inv.cwd, envs: inv.env }`, status ignored as today. The tests then assert on the string (`cpd watch --ensure --wait >/dev/null 2>&1`, `cpd tui action merge 'o/r#7' --client … 2>/dev/null`), not on a parsed program: parsing shell is not needed. Two constraints from the current code:

1. Re-entrancy: `run_shell` does `COMMIT` before the child and `BEGIN IMMEDIATE` after, because the child may call the fake again (tooling/fake_tmux.rs `bin_a_run_shell_b_hook_that_calls_the_fake_again_does_not_deadlock`). With an in-process state behind a `Mutex`, the nested `Runner::run` must run with the lock released (drop the guard / commit first) or a script that calls the route again deadlocks. The test above must be kept as a route test.
2. The bin keeps spawning `/bin/sh` (it is a process boundary until mig-final): the bin builds the route with the real `Runner` of port-run, the in-process tests with a `FakeRunner`.

Without any script the nested `FakeRunner` records the call and answers exit 0 (default reply is `unverified`).

**State for the route.** Replace the disk file by `rusqlite::Connection::open_in_memory()` per `(tmux_tmpdir, socket)` in the route, behind a `Mutex`: no fsync, no leaked file, `kill-server` drops it. The same `run_commands` takes a connection from a `Backing` (`File(path)` for the bin, `Memory` for the route). `State::open(tmpdir, socket)` (read-only, used by `TestEnv::tmux_state`) becomes `FakeTmux::state(socket)` on the same connection. `Tmux::output`'s `is_dir()` check and the tests that pass a missing dir (host.rs:66) still need a real temp directory or the check moves behind the `Runner`: decision for the Lead (`TestEnv`'s tempdir is already real).

**What a test needs from `capture-pane`, `send-keys`, `display-popup`.**
- `capture-pane`: nothing runs in a pane, so a test seeds the screen with `__ctl screen %p <text>` (a `FakeTmux::set_screen(pane, text)`); `-p` prints it, no `-e` escapes. A test that reads a rendered TUI (tui_plan.rs 9 uses, tui_widgets.rs 3) must render with `ratatui::TestBackend` instead (ADR 0013, per-file plan: "unit (TestBackend)") and not use `capture-pane`.
- `send-keys`: the route records `KeyLog { pane, keys, literal }` (`State::keys`). Tests that drive a live TUI by keys or SGR mouse reports (`tui_logs.rs:230`, `tui_merge.rs:197`, tui_plan.rs 13 uses, tui_widgets.rs 12) cannot run on it: they call the view's own event handler (unit) or are dropped (ADR "X (delete)"). Whether the views' event loop takes an injectable event source is `unverified`.
- `display-popup`: the route records the argv (`State::popups`). `dialog::ask_with` then reads the result file named in the popup command (`--out`, built by `view_command`): the route needs a scripted popup answer, `FakeTmux::on_popup(|argv| -> Option<outcome-file contents>)`, that writes the file the product will read (real fs, a tempdir path, as `temp_path` makes it) before `run` returns. Without it the confirm/input/select/checklist dialogs return an error (G5).
