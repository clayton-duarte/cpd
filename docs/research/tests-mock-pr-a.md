## 3. Tests that test an external

No test is a pure test of git, tmux or the OS: every one drives `cpd`. Borderline, for the design Job to decide:

- `two_rebases_of_one_pr_at_once...` (`pr.rs:3387`): half asserts git's own ref-lock timeout and concurrent `rebase` against one repo (`core.filesRefLockTimeout`, `run.rs:25`); the CAS half is ours. Becomes a contract test on a fixture (real git, adapter exception) plus a store-level CAS test.
- `a_slot_held_by_a_killed_gate_is_free_at_once` (`pr.rs:4106`): tests that `flock` is released when the holder is SIGKILLed and not inherited by the hook child. That is OS behaviour; our part is that `Slots` closes the fd before `exec` (`gate.rs:118-136` has a unit test of the same, `unverified` it covers it). Candidate to delete.
- `poll_says_a_gh_that_hangs_past_its_deadline...` (`pr.rs:2822`): the kill of a hung process is `core/src/host/deadline.rs` (unit-tested there, `deadline.rs:150-200`). Duplicate; delete or keep one fast case.
- `a_gate_worktree_left_by_a_killed_run_is_swept_and_a_live_ones_is_kept` (`pr.rs:1052`): ours (`snapshot.rs:40-61`) on real `worktree add --lock --reason`; not X, but needs real worktree metadata: G contract test.
- The `GH` shim scripts (`pr.rs:28-44`, `pr_view.rs:11-23`) are not tests; the `has_open` helper (`pr.rs:2736`) runs `lsof` on macOS: a real external in a helper.

## 4. Leak and flake risks

1. **Orphan hook processes, up to about 60 s.** The pre-merge hook runs as `sh -c` with `.process_group(0)` (`core/src/git/hooks/exec.rs:121`), so it is outside the env's process group. The teardown stops the env's group, the tmux server and the pids cpd records (`common/mod.rs:100-111`); "a process that leaves the group ... and that cpd does not record is not stopped". `paused_gate` and the slot hook loop `sleep 0.1` until `gate-go` exists or 600 rounds (`pr.rs:428,4135`). If the test panics before `release_gate` (`:440`) or after the SIGKILL of `cpd` (`:4116`), or `Child::drop` kills `cpd` (`:2726-2733`), the shell keeps looping with its `sleep` children after the teardown removed the directory. Applies to `:972, :3336, :3361, :4105, :4127`. Inference from reading the code; not reproduced.
2. **Real tmux server in `:2548`** (`pr.rs:2551-2553`): panes run `sleep 120` (`SLEEP_SECONDS`, `common/mod.rs:75`). The teardown kills the server and its panes (`stop_tmux`, `common/mod.rs:195-210`); a failed teardown leaves a server and two 120 s sleeps. `window_names` (`pr.rs:3004`) reads it back.
3. **Real tmux client from the product** in 8 poll tests, `:1442` and `pr_crud.rs:1792`: `tmux list-panes` against `TMUX_TMPDIR`; no server starts it (`list-panes` does not start one: `unverified` on tmux 3.8 macOS), so no leak, but the tests depend on a `tmux` binary being installed and on its message text (`host/tmux.rs:951-957`).
4. **Load-dependent timeouts.** `wait_until` is 30 s (`common/mod.rs:388`) and `await_gate` 120 s (`pr.rs:436`); on the Mac at load 40-120 a gate also needs `fx` (about 20 git processes), the `open`'s own `fetch` and `worktree add` before it starts, so `:4045, :4127, :2745` can time out. `a_second_poll_waits_for_the_lock` (`:2746`) also needs `/proc` or a successful `lsof`; `has_open` returns false when `lsof` fails (`pr.rs:2740-2741`), so it only waits out the 30 s and panics.
5. **Weak pass of `:1471`.** The 1.5 s sleep (`pr.rs:1482`) asserts "still waiting"; if the child `cpd` has not reached guard U by then (cold start at load), the assertion passes without having tested the wait. Not a flake, a false pass.
6. **Slot tests wait a real second.** The product sleeps `Slots::POLL` = 1000 ms between rounds (`slot.rs:30,98`), so `:4045` and `:4128` each take at least 1 s after the holder lets go; the test cannot shorten it (`Slots::new` has no override).
7. **Cost, not leak.** Every one of the 217 tests but 6 (`pr_view`) builds git repos (section 2.1), plus a reaper `sh` per env (`common/mod.rs:714-770`, 217 reapers, each reaped by `teardown`) and a `sqlite3` CLI call in the teardown (`:664`, `:123-170`). On macOS the teardown uses `ps -E`, `uname`, `perl` (`common/mod.rs:100-111`).
8. **Short children outside the env.** `Command::new("true")` (`pr.rs:1056`, reaped at once, `:1057`) and `lsof` (`pr.rs:2738`, `output()` waits for it) are started with plain `std::process::Command`, not `TestEnv::command`, so they are outside the env's group; both end before the test continues. No leak found.
9. **Not found:** no test in the four files starts a real `pi`, `gh`, `curl`, `ssh`, `plannotator` or the network (`DENIED_TOOLS` writes denying shims, `common/mod.rs:749-752`; the `GH`, `pi` and `node` shims are scripts in the env). `local_origin` rewrites the GitHub URL to a local bare repo (`common/mod.rs:1018`), so `fetch`/`push` never reach the network (`unverified` for `pr_crud.rs` tests that leave `origin` at the unreachable GitHub URL and run `plan lock`: `drop_unreachable_origin` at `pr_crud.rs:839` removes it first).
