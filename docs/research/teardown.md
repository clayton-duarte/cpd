# Teardown audit

Job `teardown-audit` of Plan `hardening` (hs-d34, hs-d39, hs-d51, A9). One question per resource: what puts it up, what takes it down, and when nobody needs it any more. A resource with no teardown is a **GAP**. This file proposes fixes; it changes no code.

## Method and evidence

- Read at commit `49dc6ab` (`core/`, `cli/`, `tui/`, `pi/`, `scripts/`), contract §3.4, §6, §7 and commands.md §4, §9–§12. pi 1.2.0 and `@plannotator/pi-extension` 0.28.17 were read only for when their processes and servers end.
- What I **ran** (and cleaned up; nothing of the machine's was killed or removed):
  1. `cpd events follow` with its stdout piped to a reader that exits at once, in a private `$CPD_HOME` with no Events: the follower was still alive after 3 s. (G1)
  2. `tmux -L x kill-server` and a server that exits by itself, each under a private `TMUX_TMPDIR`: the pane processes died, the server died, and **the socket file stayed in both cases** (tmux does not unlink it). (§ Tests, stale sockets)
  3. `scripts/cargo.sh test -p cpd --test driver --test e2e --test tui --test tui_plan --test session --test watch --test host` and `npm test`: all green; before and after, no new `cpd`, `tmux` or `sleep` process (the processes that appeared in between belonged to another Worker's `ssh`), no new `/tmp/cpd-test-*`, no new socket in `/tmp/tmux-$UID/`, no new `/tmp/cpd-feedback-*` or `/tmp/pi-test-*`. So a green run leaves nothing behind; the test gaps are on the panic, kill and timeout paths.
  4. `ps`, `ls /tmp`, `ls /tmp/tmux-$UID` (read only) for what exists now.
- Anything I did not read or run is marked "inferred".
- Not cpd's to tear down, listed so nobody looks for it: pi's own session files (`~/.pi/agent/sessions/`, 182 directories, 274 MB now), `~/.pi/plannotator-review-status.json` and `~/.plannotator/` (plannotator's own; for a Plan's Lead cpd points `PLANNOTATOR_DATA_DIR` at `run/<plan>/plannotator`, `core/src/host/pi.rs:lead_env`), pi's `/tmp/pi-bash-*.log`.

## 1. tmux

Every tmux call is `tmux -L <socket> -f /dev/null …` (`core/src/host/tmux.rs:Tmux::command`). **No code outside tests ever runs `kill-server`, `kill-session`, or `kill-window` on anything but a Worker window, an engine window, a Lead pane or a Worker view pane** (grep of `core/ tui/ cli/src`: `kill_pane` and `kill_window` only). `remain-on-exit on` is global (`SERVER_OPTIONS`), so a dead pane keeps its window until something kills it.
