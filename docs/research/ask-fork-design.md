# cpd owns a fork of the ask_user_question widget: design, sized into Jobs

Plan `ask-limit`, Job `teach-design`, Attempt 1. Read 2026-10-23. Research and design only: no code, skill or other doc was changed, nothing was copied or installed.

## Question

The User decided (2026-10-23, Context record hs-d593) that cpd forks `@juicesharp/rpiv-ask-user-question` and owns it, so cpd can write its tool description and state G2's limit (`pi/lib/askguard.ts:4` `LIMIT` = 1500) where the model reads it. How is the copy made, loaded for Leads and Managers only, kept from loading twice, given the description, kept current, tested, and split into Jobs, so the User can approve it?

Answer in short: a copy of the 43 `.ts` files of version 2.13.8 in `pi/ask-user-question/` (the precedent is `pi/compact-tools/`), with no new dependency (the two `@juicesharp/*` imports are dropped, 8 constructor parameter properties rewritten), registered by the adapter's `pi.extensions` and gated on the environment, standing down while the User's settings still name the npm package, with the limit sentence built from `LIMIT` by one new module. One PR, seven Jobs.

## The double load

The helper is written again, not imported from `compact-tools-double-load.ts` (about 40 lines): it is a copy that upstream owns, and sharing would couple two copies' update procedures (guess: acceptable; the other way is a shared module in `pi/lib`).
