## Summary

1. **Work: sound core, weak edges.** The schema matches contract §4.4, Events are tied to their transactions, and the merge, ladder and locks are well tested. Every serious defect is at a boundary:
   - A commit made after `attempt submit` is merged without any check (engine-W1).
   - A spawn failure burns the retry ladder: 6 Jobs failed this way (engine-W2, fixed by the open pi-pin `ladder` PR).
   - No git, tmux or poll subprocess has a deadline, and some run under locks or inside the engine's single-threaded tick.
   - An old process keeps writing after another process has migrated the store (store-W1).
   - Nine tests call the real `gh`.
   - The engine never writes `watch-stopped` (19 starts, 0 stops).
   - Unknown Event kinds cost the adapter one turn per Event.
2. **CI and tests.** `main` is red at `c565515` on `e2_kills_the_window_of_a_dead_parked_lead`, one of the nine tests that reach the real `gh` (I did not diagnose the failure). `ubuntu-latest` moves to Ubuntu 26 tomorrow, 2026-10-19 (pi-ci-W8).
3. **Fast: SQL is not the bottleneck.** An engine tick is 0.3 ms of SQL. The measured costs:
   - The Rust test run is serial: 175–200 s locally, about 54 s with the binaries run in parallel.
   - `plan show` scans the whole `history` table: 9.4 ms now, and it grows with history.
   - The widgets, statusbar and (since tui-dots) tree views re-read 1.4–1.65 MB/s each while idle (live, re-measured).
   - `history` is 80 % of the database.
   - The dev profile's full debug info costs 4.4 GB per worktree.
   - sccache, now warm (96 % hits), has not yet made the CI `rust` job faster (339 s against 307 s before).
4. **Good: mostly duplication and dead code.** Six warnings are printed on every build and nothing gates them. The ledger is written twice, the open-the-store block is pasted 23 times, there are nine terminal set-ups and four ways of following Events, and test helpers are copied into 10–12 files.

- **The schema is the contract.** All 52 objects of §4.4 match the live database byte for byte, and the 36 generated history triggers list every column. The live hash equals `SCHEMA_HASHES[5]`. `PRAGMA integrity_check` and `foreign_key_check` are clean. All 41 Event kinds agree between §5.2, `kind.rs`, the DDL and the adapter's `KINDS` ([store](quality-store.md#already-good-keep), [pi-ci](quality-pi-ci.md#already-good-keep)).
- **Events cannot leave their transaction.** `append` takes a `&WriteTxn`. `events.at = txns.at` holds for every row, and ids never decrease against `txn`.
- **Migrations** run as one transaction under `store.lock`. Pragmas are restored on both success and failure, and foreign keys are checked before the commit. Every old version is tested with data.
- **The engine is cheap and steady.** An engine tick is 0.3 ms of SQL. The engine stays at 12–14 MB with flat RSS, a driver at 11 MB. An idle `events follow` makes four syscalls and no reads ([sql-perf](quality-sql-perf.md#already-good-keep), [engine](quality-engine.md#already-good-keep)).
- **Compare-and-swap everywhere.** `ledger::end`, `update-ref old new`, E4 re-checking its condition inside the transaction, and the cancel safe points. R (recovery) is idempotent and covered by 34 merge tests.
- **Locks the kernel releases** (engine, driver, per-repo). fd 3 is close-on-exec and kept across `exec`. `Report` emits one error per (step, object, code).
- **Hooks** run in process groups that are killed at the deadline. Hook environments are scrubbed (teardown G8 is fixed).
- **The command layer.** Every refusal that was run returned the documented code and exit. There is one JSON envelope and one `ErrorCode` table. Ids are parsed at the boundary. `job` commands are idempotent by construction. The `gh` gateway is typed, with timeouts. `pr poll`'s no-op path writes nothing ([commands](quality-commands.md#already-good-keep)).
- **The views.** The terminal is restored on every error path, and there is no `unwrap` on read data. The coalescing rules of §17 are implemented, the start is gap-free, the actions are commands rather than writes, and the tree view has 46 unit tests ([tui](quality-tui.md#already-good-keep)).
- **The adapter** implements §15 closely and is tested through real boundaries: a fake `cpd` on `PATH` and 66 tests. The cursor design, idempotent handlers and serialised state reports are all sound. `install-cpd.sh` refuses a build older than the store ([pi-ci](quality-pi-ci.md#already-good-keep)).
- **The test suite and harness.** No flake appeared in 4 full passes plus 25 stress runs, and the hs-n12 fix holds. `HOME`, `CPD_HOME`, tmux and git are isolated per test. All 64 commands and all 116 error codes appear in a test. Waits poll with a deadline and a message ([tests-build](quality-tests-build.md#already-good-keep)).
- **Builds and CI.** Incremental builds take 2–4 s. Every dependency is pinned once, with its reason. CI runs the same four commands as the Gate, with `contents: read`. `npm run typecheck` takes 0.5 s.
