## Reviewer feedback (verbatim)

Blocking: tamperCheck in src/git/gate.ts can be bypassed by renaming a forbidden file. It calls diffNames(worktree, `${base}...${branch}`) with no extra flags, i.e. `git diff --name-only -z base...branch`. git diff detects renames by default (diff.renames defaults true) and --name-only prints only the post-image name. So an Attempt that commits `git mv .config/wt.toml .config/wt.toml.bak` (also verify.sh, or a file under .cpd/) reports only the new, non-forbidden name; `wt merge` then finds no project config, runs no pre-merge hook, and the merge and the post-merge Gate both pass trivially. This is the Gate-bypass t3 F11 says must be blocked. I inferred this from the git man pages on the machine, not by running it. Fix: (1) in src/git/gate.ts call diffNames(worktree, `${base}...${branch}`, ["--no-renames"]) (diffNames already accepts `extra`), so the old path appears as a deletion. (2) In test/git/gate.test.ts add tests where an Attempt commits `git mv .config/wt.toml .config/wt.toml.bak` (unchanged content) and likewise `git mv verify.sh verify.old`; tamperCheck must include `.config/wt.toml` and `verify.sh` respectively. Confirm they fail before the fix. (3) In test/git/merge.test.ts add a case where an Attempt that only renames .config/wt.toml gets result 'tampered' (files include '.config/wt.toml') with the Lead ref and worktree unchanged. Everything else (Gate exit=0, all acceptance items covered by real git/wt tests, file ownership, zod/argv/exit-code conventions) is fine; do not rework it. Non-blocking: mergeAttempt holds the merge lock across two Gate runs but uses withLock's default 60 s wait, so a queued merge may hit lock_timeout with a ~50 s Gate; note this under Escalations or pass a longer timeoutMs.
