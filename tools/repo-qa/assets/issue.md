## Problem and intended behavior

Concrete impact, expected/actual behavior, and the documented intent source.
Severity: critical / high / medium / low. Confidence: reproduced /
source-confirmed / investigation. State unknowns and mitigation (or none).

## Evidence

Repo and base SHA; affected paths/permalinks; environment/tool versions;
self-contained reproduction command and minimal fixture, expected/actual output.
Follow real callers and verify the claim against current base. Preserve evidence
that contradicts the initial hypothesis. Do not rely on a temporary file URL.

## Research and decision

Official sources/upstream versions and access date; relevant prior art/history;
alternatives including deletion, existing OSS and the smallest local fix;
recommendation/tradeoffs and lasting documentation link. Distinguish evidence
from User policy and proposed decisions. Do not claim consensus from one source.
For `needs-human-input`: exact unresolved question, options and recommendation.

## Acceptance criteria

Observable outcomes and focused checks, including relevant failure/recovery
cases. A regression should fail on the original code and pass on the fix.

## Scope and links

Owning repo; duplicate searches across open/closed issues/PRs; dependencies,
active fixes, exclusions and follow-ups. Preserve injected budget markers.
